# Files

The pipeline lives in `pipeline/`; paths below are relative to it, apart from `prompts/`. Run the scripts from `pipeline/`. Modules in `lib/` are only imported by them.

## Pipeline steps

| File | Role |
|---|---|
| `run_api.sh` | Runs the steps below for one book, in one command |
| `batch_api.sh` | Several books in parallel, with a batch cost gate and a summary (needs `AUTO=1`) |
| `intake.py` | Untagged originals only (a placeholder tag tree with no text structure counts as untagged): page triage, text-layer test, OCR (OCRmyPDF + Tesseract) and auto-tagging (OpenDataLoader), with checks after each step. Local, no model. `--plan-only` shows what it would do without changing anything |
| `audit.py` | Original → digest (styles, listed elements, figures with crops, page map, reading order, front matter; in scanned books, suspect OCR words on word sheets; veraPDF's PDF/UA failures). No model. Positions are measured in the visible page area (CropBox): running-head bands (top 70 pt, bottom 60 pt), figure sizes and crops; a figure drawn only outside it gets no crop and is marked `outside_visible_area`. The whole texts the digest shortens (elements, first list items, first table rows), and the full reading order of the containers for the review page (with each container's child styles), go to `fulltext.json` beside it, for review.md, review.html and the review page only: never sent to the model, kept in the run's `reviews/_audit/` with the digest (not the crops) for a later review |
| `decide.py` | The API call. Estimates cost, checks available credit, sends the digest and crops, parses and validates the reply. `--dry-run`, `--response-file`, `--check-key`, `--credit` (credit left), `--max-images` (default 100), `--max-tokens` (default 48,000, or 16,000 plus 45 per OCR word form sent when that is more; the model's reasoning counts against it) |
| `apply.py` | The executor. Original + work order → `<original>_remediated.pdf`. pikepdf only; checks each target first and rejects what doesn't fit |
| `verify.py` | Checks the result against the original, adds the WCAG checks veraPDF does not make, and runs veraPDF on the result |
| `report.py` | Writes `review.md` (with its "Overview"), `record.json` (with `glance`), `han_review.csv` and `review.html`, then removes the working files, keeping the digest, `fulltext.json` and OCR word sheets in `reviews/` (and a review as session 1). `--input` (from `run_api.sh`) records the input's path; `--from-record` and `--intake` are for a re-apply |
| `report_html.py` | The offline dashboards: `review.html` for a run (`report.py` runs it) and, with `--summary <batch>`, `summary.html` for a batch (`batch_api.sh` runs it). Also rebuilds them for any finished run. See [Output files](output-files.md) |
| `vera.py` | Runs veraPDF with the pinned WCAG 2.2 machine profile (which includes the PDF/UA-1 rules) and condenses its report to one entry per failed rule: WCAG or PDF/UA-only, and who can fix it (and, for the AI, the work-order key). `--check`; or `vera.py FILE.pdf OUT.json` on its own |

## Review and tools

Writes `review.json` and the reviewed `workorder.json`. On a finished run: `--reopen [--from N\|ai] [--no-apply] [--discard-open]`, `--discard-open` on its own (the open session marked abandoned), `--sessions`, `--apply`, `--pin [--pdf FILE]`, and `--replay-to DIR` (a run that can no longer be reviewed: its intake and saved reply copied for a new run on today's code). `--return-to URL` (with `--serve` or `--reopen`): the page to go to after Finish (the app's run page). See [Reviewing the work order](review-step.md) |

See [The OCR text](review-step.md#the-ocr-text) |

| `webapp/downloads.py` | A run's versions and their downloads: the version list (only versions whose PDF exists; after clearing, the shipped copies), the names, the files opened in one moment under the record lock, the streamed record ZIP and its read-me, and `release/downloads.json` (a complete record ZIP of a live shipment) |
| `webapp/home.py`, `webapp/home.js` | The home page ([The home page](home.md)): the PDFs, runs in progress, My Workspace (single runs and batches, cached in `runs/.app/home-index.json`, with status groups and pages), the "Upload a PDF" drop zone (several PDFs at once), the "⋯" menus and Edit Name in place, the app bar on every page but the home page |
| `webapp/lang.py` | "Language of the Scanned Pages" (#45 D4): the question from `_intake/languages.json` (or intake's CJK stop), its evidence in plain words, and the answer's environment |
| `webapp/trash.py`, `webapp/trash.js` | "Move to Trash" (#45 D8): a run, a batch whole or in part, an added PDF; the plans the confirmations show, the refusals, the moves, `runs/.app/trash-log.json` ([The app](app.md#move-to-trash)) |
| `webapp/names.py` | The names people see, the app's only: book names (`runs/.app/book-names.json`), plain run and batch names (`runs/.app/run-names.json`), the automatic cleanup of a PDF's Title, and the folder label a plain name becomes |
| `webapp/books.py` | The PDF list (the uploads only; samples/ is searched by sha256 for originals, never listed), display names (`runs/.app/books-cache.json`), Upload a PDF (into `uploads/`, never replacing a file), the OCR language choices |
| `webapp/newrun.py`, `webapp/spend.py` | A single run from the home page: New Run's form, the free estimate job, Try Again decided from disk, New Run from the Saved Reply; `spend.py` is the one gate every "Start Remediation" goes through (the fingerprint, the model and prompt, the limits, MAX_USD), and every app run sets REVIEW=1; the "Language of the Scanned Pages" answer |
| `webapp/batches.py`, `webapp/batch.js` | Batches from the home page: the book list (`runs/.app/batches/<label>.books.txt`) and record, per-book estimates, totals, the batch's "Start Remediation" (batch_api.sh), the batch page and the side column |
| `webapp/failures.py` | Why a run stopped, in plain words, as a table by step, with the tool's own words only under "Details" |
| `lib/costs.py` | The cost estimate interface: a step's worst case, limits and credit, the fingerprint, the bounds a "Start Remediation" passes on (MAX_USD, BOOK_MAX_USD, BATCH_MAX_USD), the actual cost after, a batch's totals; `expected` is #65's (dollar-only cost limits) hook |
| `review/clear.py` | "Clear This Book's Files" for a shipped book: the gate, the PDFs and images it deletes, `release/cleared.json` ([Accessibility evaluation and release](release.md#clearing-a-shipped-book)) |
| `review/prune.py` | "Clean Up Space": the previous versions whose PDF can go (never the current version, the AI's own, an evaluated or a shipped one), and the removal of the ones a person selects under `reviews/.lock` and the record lock, recorded in `release/removed.json`; `review_workorder.py --remove-older-pdfs` is its command line |
| `manual_checks.py` | The accessibility evaluation from the terminal: `--show`, `--record pac\|screen-reader FILE.json [--for-sha SHA]`, `--refresh`, `--template pac\|screen-reader`; through `review/manual.py` |
| `review_ocr.py` | Records a person's verdict on a book's OCR text (checklist rule 2): `python3 review_ocr.py <run>/<book> --verdict approved\|"not approved"\|"sent to a language reader" --reviewer NAME [--reason TEXT] [--pages 381-386] [--reads LANGUAGE] [--to WHO] [--date YYYY-MM-DD]`, through `review/ocr.py`, the same code as the review page's OCR Text section. Writes `_intake/intake.json`, `record.json` and the review.md row, and refreshes "Overview" and `review.html`; the row is OK only on "approved"; FROM= reruns carry the verdict. For a finished run, refused while a review page of the run is open or an apply runs. `--serve` opens the OCR-only review page |
| `scan.py` | Fast read-only checks on a folder of PDFs (no OCR, no model): tagged, placeholder tag tree or untagged, MarkInfo, producer, page triage (pages whose text draws no character counted by their images), private-use characters, text outside the visible page area and word breaks, per book (`books/*.json`) and in `summary.md`: `python3 scan.py <folder> <out_dir>` |
| `tools/compare_runs.py` | Are two runs' `review.md` files the same, book by book? `python3 tools/compare_runs.py <label-a> <label-b>` (a batch folder under `runs/batches/`, or a prefix naming several: `s1` → `s1-g1`, `s1-g2`, …). Byte for byte, leaving out only the two lines that change on every run ("Time:" and the run-start line); one line per book and a total; exit code 1 when any book differs. The acceptance test when `review.md`'s writing code changes: rerun the same books with `FROM=` before and after, then compare. See [Batch runs](batch-runs.md) |
| `tools/intake_cases.py` | Synthetic test PDFs (no book content) for intake's classification: an empty text object over a scan, an OCR layer, a text page, placeholder and real tag trees (MarkInfo missing/false/true, Figure-only with alt), Japanese, vertical Japanese and Korean scans with and without `OCR_LANG`. `python3 tools/intake_cases.py <out_dir> [--full]` runs `intake.py --plan-only` on each and prints PASS/FAIL per case (SKIP for the CJK cases when no CJK font is installed; `INTAKE_CASES_FONT` names one) and a summary line; `--full` also runs the whole intake on the two placeholder-tree cases. Local, no model |
| `tools/reorder_case.py` | `move_section` on a real book's tag tree: swaps one section with the next in a copy of a tagged sample (default hawaii3; pages unchanged), runs `run_api.sh` on it with a hand-written reply holding only a `move_section` that undoes it, and checks the audit's flag, the review page's preview, apply's move and log, the restored order and verify's section check. `python3 tools/reorder_case.py [--book hawaii3] [--out DIR]`; PASS/FAIL per check, exit 1 on any FAIL. Local, no model, veraPDF off; about 3 minutes |
| `tools/regression.py` | The regression test: reruns the baseline books (`tests/baseline/`) from their saved replies (no API call) and compares `record.json` fields and `review.md` with the baseline, plus checks that must always hold. `--update --reason "…"` writes a new baseline; `--seed RUNS_BATCH_DIR` copies the replies after a prompt change. | `tests/` | The unit tests (`python -m pytest tests -q`) and `tests/baseline/` (the regression baseline: per book a saved reply, `review.md` and `expect.json`; `meta.json`; `UPDATES.md`, why each update was made). See [Testing](testing.md) |
| `requirements-dev.txt` | `requirements.txt` plus pytest, pinned: `pip install -r requirements-dev.txt` to run the tests |

## Shared helpers (`lib/`)

| File | Role |
|---|---|
| `lib/tablegrid.py` | Who heads what in a table, from its cells' spans and the work order's reading of its rows; refuses a reading that doesn't fit. Used by `apply.py`. No PDF here. |
| `lib/workorder_check.py` | The checks every work order goes through before `apply.py`: used by `decide.py` on the model's reply and by `review_workorder.py` on a reviewed order |
| `lib/support.py` | Says whether the pipeline supports a PDF: PDF 2.0 and namespaced tags are not supported yet. `intake.py` stops such a book for a person; `audit.py` and `apply.py` check again; `scan.py` reports it |
| `lib/gaptext.py` | Text as a reader hears it: a space where the PDF has a gap but no space character (over 0.10 em and 2.5 × the line's typical gap; not where another tag's glyph fills the gap). Used for the digest and review.md, and for matching text rules; never changes the PDF |
| `lib/listrule.py` | The one-item list rule, shared by `audit.py` (marks the lists in the digest) and `apply.py` (applies it) |
| `lib/readorder.py` | The reading-order rules: which tags count as sections, which sections are read away from their printed place (`verify.py` and the review page), and the one `move_section` match `apply.py` uses and the review page previews. Also the digest's one-line form of a section |
| `lib/scripts.py` | Which CJK script a run is in (hangul, kana, Han-only, mixed with Latin) and what language tag it needs against the document's language; shared by `audit.py` (the digest's `cjk_runs`) and `apply.py` (the language step) |
| `lib/ocrwords.py` | Which OCR words in a scanned book look misread, and where words break (spaces, and gaps by `gaptext.py`'s rule); used by `audit.py` for the word sheets. See [OCR words](ocr-words.md) |
| `lib/langtag.py` | Checks and tidies a BCP 47 language tag; used by `apply.py` (`/Lang` spelling) and `decide.py` (the work order's `document.lang`) |
| `lib/sections.py` | `review.md`'s content as data: `report.py` writes its lines as before, a line can carry a key, its pages and the parts only PDF/UA requires; `to_sections()` turns them into `record.json`'s `sections` and `render_md()` gives back `review.md` line for line. `review.html` leaves out the PDF/UA-only lines and parts by this field, not by matching phrases |
| `lib/origin.py` | The AI call behind a run's work order (checklist 11.5): a reused reply (FROM=, REPLY=, a review's re-apply) carries the original call's cost, model, prompt and date, from `run.original_call`, a reply's `.meta.json` or a record beside the reply with the same reply text; `record.json` `ai_call` with the cost per page; "not recorded" only when none is kept anywhere |
| `lib/release.py` | The accessibility evaluation's rules, with no writing: the checklist (once, for the page, the command line and review.md) and its retired items, checking results, which results count for which file (by sha256), completeness and issues noted, the evaluation line, the status (Not Ready, Pending Evaluation, Ready, Shipped), and review.md's evaluation section |
| `lib/dates.py` | Dates and times as a person reads them ("October 31, 2026", "4:32 PM"), wherever the app, the dashboards and review.md show one; the same rule in `webapp/panel.js` and `review/page.html` |
| `lib/runlock.py` | The record lock: one writer at a time of a finished run's record.json, review.md, review.html and release/ (`<run>/.record.lock`, flock, not re-entrant, a bounded wait) |
| `lib/glance.py` | The "Overview" numbers for a finished run (status, ready to ship, five safety checks, the veraPDF finding, needs a person, AI decisions, fixed automatically, veraPDF, top issues), from `record.json` and `review.md`; shared by `report.py`, `report_html.py` and `review_ocr.py` |
| `lib/plpages.py` | Reads each page once with pdfplumber and keeps only what `audit.py` and `apply.py` use: characters, image boxes, size and the visible area (CropBox) |
| `lib/plumb_fix.py` | Fix for pdfplumber's nested marked-content bug (required; imported before pdfplumber reads a page) |

## Prompt and veraPDF data

| File | Role |
|---|---|
| `prompts/workorder_v10.md` | The system prompt: rules and the work-order format. Its hash is recorded in every run. v10 reads a table's rows from the digest's `row_shapes` (`title_rows`, `note_rows`, `group_rows`, `repeat_rows`) and stops counting a title row as a header; work orders from v9 are still read. v9 (schema `workorder/0.2`) makes `move_section` a list of up to 3 moves, made in order, and lets the model turn the figure-order step off for a book (`fix_figure_order: false`, for figures meant to be read apart from their page); work orders from v8 (one move) are still read. v8 adds `tables` (header rows and columns of a real table), lets `rolemap` map a style the source never mapped, tells the model the work-order key and tags for each `pdfua_check` rule, and requires every such rule to be fixed or deferred by name (step 9). v7 changes the ActualText wording (spoken text only where printed glyphs read wrongly; equal to the print apart from spacing, case and line-end hyphens; merges join a label and its title) and adds `ocr_words` (the printed spelling of misread OCR words in scanned books, read from word sheets) and `pdfua_check` (the veraPDF failures the model can act on). v8 and older are kept as a record |
| `verapdf/` | `WCAG-2-2-Machine.xml` (the pinned profile), `rules.json` (each rule's WCAG success criteria, or why it is PDF/UA-only), `install.sh` |

**Figure images** are sent as JPEG (long side 800 px). If a book's images together pass 20 MB they are made smaller step by step, because OpenRouter refuses requests with more than 30 MB of images (HTTP 413). At most 100 images go in one request (Anthropic's limit). In a book with more figures, the alt text for the rest goes to a person, listed in the review under the AI's deferrals. What was sent is recorded in `record.json` under `run.images`. In the sample books, *dwellings* sent 100 of 543 figures and *dakine* 100 of 113.
- **The cut follows book order, not importance.** Figures go in the order the digest lists them, with whole-page figures (maps, plates) after all of them, so in a long book the cut falls on late figures and page figures first.
- **The model still sees a figure that was cut, but only as text**: its page, size and the text near it. Any alt text it writes for one is dropped as written unseen. It can still mark one as decoration, which hides the figure from screen readers on the strength of that text alone, so check those decisions in the review.
- **OCR word sheets share the 100 slots,** after the figures (see [OCR words](ocr-words.md)).
- **With `REVIEW=1`,** every figure left without alt text is listed as a gap at Finish, and the reviewer can write the alt text on the review page (see [Reviewing the work order](review-step.md)).

## Where records live

**A record is never an image or a PDF.** `_audit/` and `reviews/_audit/` hold what the pipeline extracts from the book:
records (the digest, its full text, dryrun.json, the OCR-word list, all `.json` or `.csv`) and figure crops and page
images. Clearing a shipped book removes the PDFs and images there and keeps every `.json`, `.md`, `.html` and `.csv` file ([Accessibility evaluation and
release](release.md#clearing-a-shipped-book)). A new record goes beside record.json, in `reviews/` or in `release/`.

**The app's own files** are in `runs/.app/` (the `jobs` setting): `jobs/<id>.json` and `.log` (each job, its environment,
its log), `dispatch.lock`, `server.log`, `sha256-cache.json` (books' hashes), `books-cache.json` (titles and page counts),
`home-index.json` (the earlier-runs list), `book-names.json` and `run-names.json` (names, `names.lock`), `batches/<label>.books.txt` and `.json` (a batch made in the app).
**`uploads/`** (repository root, git-ignored) holds the PDFs added with **Upload a PDF**, each with a `<name>.json` note. A run's
`_intake/languages.json` is intake's `--languages` result; a batch folder may hold `ocr_langs.tsv` (each book's OCR language)
and `trashed.json` (its PDFs moved to the Trash, with their cost).
